# Capsules that decline `semantic.must_accelerate` on work their target's capability contract
# ADMITS, without stating a `not_asserted_reason`. THIS FILE MAY ONLY SHRINK.
#
# Measured 2026-09-02: build_tools/scripts/check_mesh_assertion_not_weakened.py.
# 169 capsules sit on an admitted (family, dtype) cell; 26 decline the demand
# with no reason, and 9 of those are HAND-AUTHORED -- the reference set the automation
# is being built to reproduce.
#
# HOW THIS HAPPENS: a regeneration emits its own default for `semantic`, the hand-authored
# assertion is not in its vocabulary, and the field decays. The repo already paid for this once
# when regeneration deleted `pass_requirements` from the only two capsules that had it. Measured
# here: six hand-authored microscaling capsules went from `must_accelerate: true,
# fallback_allowed: false` to `must_accelerate: false, eligible: auto` on a target whose contract
# admits contraction at mxfp4, mxfp6 AND mxfp8 -- so the work is eligible and the weaker value was
# not a decision about the hardware. Three more (MH0/MH1/MH2) are gitignored hidden capsules, so a
# git diff cannot see them at all; only this derived invariant catches those.
#
# THE FIX IS NOT NECESSARILY `true`. A capsule may decline the demand -- some MX paths genuinely
# cannot be accelerated on the MLIR route -- but it owes a `not_asserted_reason` saying which.
# Declining silently is what this gate rejects. 24 capsules already carry that field.
