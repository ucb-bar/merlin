# How this deliverable was checked

**Result.** The source/claim matrix passes all 31 audit consistency checks at verification `58dbc7c00` and producer `4499eebb9`. The selected behavioral suite passes 530 tests with no failures, errors or skips. No Lean qualification or human semantic approval is claimed. The checks establish the reported inventory, source associations and evidence status; they do not prove the compiler or the IR-to-Lean projection correct.

**Classification decisions a reviewer should know.**

1. **Configuration elision is unqualified.** The diagnostic review README describes successful-sounding workflow/evidence, but the [active record](../../graph-state-elision/active/README.md) (line 145) records a SIGSEGV at the fifth original boundary, zero qualified originals/replays, and no replay batch. No rerun or identity substitution was attempted.
2. **Candidate stages are counted by actual behavior.** Configuration, fusion and prefetch stage specifications are nonmutating in `PipelineSession`, but create candidates later consumed by storage, so those transformations stay in the denominator. Final encoded segmentation changes an emitted artifact even though the session IR is unchanged.
3. **Plans are separated from implementations.** `plan_connected_region` leaves source MLIR unchanged and checks a complete ordered plan/interface. Native fan-out fusion changes the Kernel; its native theorem assumes a local implementation contract. Capacity plans, callback slots and source exports are not extra proved graph rewrites. Conversely, source recomputation and row-batching plan APIs create changed module clones and are recorded as transformations.
4. **Policy dispatch is what the code does.** `execute_policy` calls `session.run` on supplied `RegisteredPass` actions; it does not call `apply_common_pipeline` and has no fixed registry of its own.
5. **Helper variants do not inherit theorems.** Separate setter/barrier retained-index cleanup and table-selected im2col packing are rows of their own, rather than inheriting the configuration-elision or bounded-packing theorem/checker. The convolution normalization checker link is its actual `verify_bounded_match` use.
6. **Family evidence is not transferred to fresh examples.** A fresh example is not one of a packet's qualified originals, even when that packet's projection admits it. A successful model projection is never labeled a kernel acceptance. Fresh variants outside a qualified composition domain are labeled outside it.
7. **Sealed packets are engineering evidence, not review.** For shape, integer v2, the four-pass chain, memory-SCF and declared-call v1, the exact root theorem statements were read and cited with their hypotheses. Each seal's local evidence is recounted rather than taken from its reported totals. The packets' own `review_complete`/`ordinary_compiler_gating` flags are false and stay false here.
8. **The live gate's identity statement is its own gap.** A sealed whole-module shape route exists, but `accepted_pipeline_receipt` still admits shape changes on `id value = value`. That is a compiler-gate defect, D1-G09, rather than a missing-proof gap.

**Executed behavioral checks.** [run-behavioral-suite.py](run-behavioral-suite.py) runs 16 existing pinned-producer test files in the producer checkout with the main checkout's `.venv` interpreter and `PYTHONPATH` set to the producer. They cover scheduling, configuration deletion/hoisting, private copies/coalescing/pipelining, storage, spills, physical fusion, final program limits, command compaction, staged tile ordering, effect cleanup, dead payload writes, recomputation and row batching. The [result](behavioral-tests/suite.json) ([log](behavioral-tests/suite.log), [JUnit](behavioral-tests/suite.xml)) is **530 passed; no failures, errors or skips**. These are behavioral observations, not qualification or proof counts. Neither compiler nor test sources were changed.

**Native environment and retained execution evidence.** The run selects an existing local LLVM build at source revision `a47bddccec30255619bb8c37fa59700e661d4e66` (`clang-23`, `mlir-opt`, `mlir-translate`, assertions enabled) and the existing `out/build/lean/mlir-venv/bin/python` compiler interpreter; nothing is downloaded. [Toolchain identities](behavioral-tests/toolchain.json) retain binary hashes, versions and environment selections. No guard, pipeline feature or test was disabled. The [native evidence index](behavioral-tests/native-evidence.json) binds the 61 files the row-batching test retained and checks 80 owner/product identities. The [original and transformed CPU pair](behavioral-tests/row-batching-native/pair.json) retains changed source MLIR, compiled objects/shared libraries and six input/output archives. The test verifies all nine outputs, ordered wrapping i32 reductions, i16 carried state across three calls per arm, unchanged inputs and guard regions. This is concrete CPU execution evidence for the tested case, with no hardware or Lean qualification promotion.

**Regenerating.** From the main checkout, with `.venv/bin/python -I`:
1. `run-behavioral-suite.py` requires an empty `behavioral-tests/`.
2. `probe-sealed-routes.py` runs the shipped shape/integer projections without Lean. It needs `PYTHONPATH=<producer>/src` for its subprocesses and an empty `projection-probes-sealed/`.
3. `build-deliverable.py`, then `audit-deliverable.py`, then `finalize-deliverable.py`.

**Practical limits.** These checks do not reconstruct every program independently from first-principles semantics, prove projection injectivity, validate concrete native instruction laws, reproduce missing original-bound replays or approve numerical/physical contracts. Raw missing bundles remain unavailable, and development/failed evidence remains at that status. The exact gaps and closure conditions are in [gaps.md](gaps.md); the requirement-by-requirement judgment is in [requirements-audit.md](requirements-audit.md).
