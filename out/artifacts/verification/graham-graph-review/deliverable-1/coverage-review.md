**What verification is trying to establish.** A compiler transformation changes one program representation into another. Its correctness claim should identify the complete before/after boundary and say which observations must remain equal: return values, visible state, failures, memory behavior, or some stated subset. Python recognizes the actual IR and builds a model. Lean checks a mathematical proposition about that model. To apply the result to the compiler, the source-to-model mapping and operation assumptions must also be justified. A hash identifies selected bytes; it does not establish that the model faithfully represents their meaning.

A changed producer example establishes that the implementation really performs the transformation. A projection success establishes that the model generator accepts that example. A kernel-checked instance establishes the stated proposition under its hypotheses. Original-bound qualification/replay checks connect the exact instance, implementation and tool inputs. Independent premise review establishes whether those hypotheses support the intended real-world claim. These are separate layers. "Engineering-qualified" below means the packet owner's frozen suite and fresh replay passed; it is none of the later layers.

The executable schedule pipeline registers admission, storage, completion, emission and final-program stages, plus optional configuration/fusion/prefetch and a selected post-storage stage. Candidate stages have `mutates_ir=False` because they produce candidates for later application. The storage action can realize those candidates, forward copies and insert spills. The flag cannot be used to erase these transformations from the denominator. Conversely, completion/emission stage names do not create additional proved graph rewrites. `finalize_program` can change encoded segmentation despite not mutating the session's schedule IR.

`PointwiseScheduleRewrite`, `PostStorageRewrite` and copy-motion callbacks are interfaces. Each concrete implementation needs its own ownership and evidence. Export membership is also separate: `library_sources` defaults to V6 and preserves separate V7/V8 rosters. Listing an implementation in an export does not prove its semantics or authorize a target implementation. The target-adapter row records the shared interface; it does not assert that Gemmini, Atlas or agent-generated OOT primitives have been independently audited here.

**Normalization, the live gate and dependency scheduling.** The old broker's shape branch literally generates `∀ (α : Type) (value : α), id value = value` or a known extent's reflexive equality. These propositions contain no actual memory program. Integer simplification checks more substantive fixed-width arithmetic, but recognizing the rewrite and preserving the surrounding program remain trusted reconstruction. `Scalar.check_sound` is not silently substituted for either branch; nor are older `MerlinVerify` numerical theorems borrowed across semantics.

This matters beyond paper wording. `apply_common_pipeline` refuses a covered change unless `accepted_pipeline_receipt` accepts the old broker's receipt. For `shape_view_normalization` that receipt is issued after kernel-checking one of the statements above (`producer:src/merlin/verify/lean_checker.py:441`). The ordinary compiler therefore records "fresh Lean completion" for shape normalization on the strength of a statement that names no program. This is not a miscompile, and the producer's structural validation still runs. But the existing live gate grants proof authority to a vacuous theorem here, and the sealed shape route is not wired to it. Recorded as D1-G09 for the coordinator.

The sealed whole-boundary routes use two structural patterns. Shape's `Model.checked_complete`, and memory-SCF's `checked_chain` likewise, relate the `false` and `true` readings of **one** projected blueprint module. The binding of that blueprint to the actual before and after MLIR is the trusted Python full-tree matcher; Lean checks `sourceBinding`/`targetBinding` only as nonempty strings. Integer v2 and the four-pass pipeline instead normalize separately projected before/after programs inside Lean (`programs_sound`, `PreservesEntries` over `originalEntries`/`finalEntries`), with `exactMiddle` equating the joined buffer. Both patterns leave projection fidelity trusted, but in the first the after-program's correspondence is entirely host-side. Deliverable 2 should audit that matcher first.

The old scheduling branch is an important exception to a blanket “only local lemmas” description: it calls `verify_scalar_transform` and proves complete returned-vector equality for one exported scalar function. That narrow result excludes general effects and additional defined functions. `GraphState.check_sound` checks the actual permutation through adjacent exchanges and proves full modeled-state equality with arbitrary sequential context, assuming total read-local/write-framed actions and complete effects. The old broker is not a consumer of that standalone leaf; its live `_COMPLETED` receipt requirements remain separate.
