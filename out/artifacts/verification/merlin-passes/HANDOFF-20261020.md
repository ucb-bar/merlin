## 3. Frontend implementation: what is proved

Claim label: **`policy "frontend-float-to-bool"`**.
The intended initialized f32 Boolean is false for either signed zero and true for
every other encoding, including all NaNs, infinities, subnormals and fractions.
Poison stays poison. This intentionally differs from truncating numeric i1 casts.
For example, +0.5 can truncate to zero in the captured cast but is true under bool
intent; signed +1, infinities and NaNs may make the captured signed cast poison.

### Actual before/after programs

`merlin/lean/MerlinVerify/Rules/FrontendBoolProgram.lean` consumes Lean-decoded,
authoritative exported IR. `intent?` inventories definitions through nested regions,
rejects duplicate IDs, derives source eligibility/types, replaces every eligible
f32-to-i1 `arith.fptosi` or `arith.fptoui`, and assigns fresh +0 IDs above all source
IDs. Unsupported source sites refuse the expansion instead of being omitted.

`check` compares the whole reconstructed intent with the actual after module using
exact `alphaOps` correspondence, `moduleCheck`, modeled comparison-key checks and
outside-function change checks. This covers operand identity, result types/uses,
predicate 13, fast-math none, positive-zero bits/type, cast removal, fresh SSA,
nested regions and unrelated operations. Python Candidate flags are not proof facts.

`FrontendBoolProgram.check_sound`, and its existential wrapper
`FrontendBoolChain.accepted_intent`, establish:

```text
check before after = true
  => exists intended, intent? before = some intended
     and for every defined function f:
       FuncRefinesC opSem True True after f intended f
```

The reference is the reconstructed comparison program. This is conditional
refinement under the existing MLIR evaluator, not equivalence to the original
cast, and not proof that all of SmolVLA executes without stuck/UB/poison.

### Concrete f32 law and actual execution

`Rules/FrontendBoolFptosi.lean` defines exactly:

```text
UneCorrect M := forall x : FBits f32,
  M.cmp uneKey f32 x 0 = (if x.toNat % 2^31 = 0 then false else true)
uneKey = arith.cmpf with fm1:0;rm4:none;pred13:attr 13 : i64
```

This quantifies initialized encodings. Eager evaluator poison propagation is a
separate proved fact. `alwaysFalse_not_une` shows why the law cannot follow for
an arbitrary unconstrained `FloatModel`.

**Proposed, not approved/default**, `Rules/FrontendF32Comparison.lean` uses Lean
4.35's existing IEEE binary32 `unpack` and ordered `UnpackedFloat.beq`:

```text
une x y = !(beq (unpack binary32 x) (unpack binary32 y))
```

`model(base)` overrides only the exact UNE key at f32, delegating all other
interpretations to `base`. `une_zero` and `model_correct` prove `UneCorrect` for
all 2^32 encodings, including quiet/signaling NaNs of either sign and all payloads.
No new axiom, invented arithmetic law or frozen-semantic edit is used.

- `model_site`: actual `Sem.Ops.opSem` computes A2's poison-aware scalar result.
- `accepted_site_exec`: at an identified generated occurrence in an accepted
  intent program, binds the A2 result and executes an arbitrary following block.
  Source lookup, occurrence, result type and source/zero freshness are explicit
  local premises. The comparison-law premise is discharged by the proposed model.
- `model_tensor`: the poison-aware coordinate extension equals A2's tensor contract.

The older `Candidate.check_sound` is a schematic initialized-f32 sanity lemma and
is not the integrated program checker. Its comment now states that limitation.

### Precise existing-host blocker

`merlin/lean/Differential.lean` already has `MerlinDifferential.hostModel`.
Its f32 comparator widens with `(Float32.ofBits bits).toFloat` before comparing.
Lean 4.35's `Float32.toFloat` is an opaque extern with no logical equation
(`Init/Data/Float/Float32.lean:556`). Unpacking, NaN tests and comparisons themselves
do have logical models. The missing bridge is specifically the widening conversion.

No universal `UneCorrect hostModel` proof was obtained. The exact remaining bridge
for this use is:

```text
forall x : FBits f32,
  hostModel.cmp uneKey f32 x 0 = FrontendF32Comparison.une x 0
```

This is not asserted as an axiom. Either review/adopt the direct IEEE instance,
or obtain an approved logical widening model and prove the bridge. Native samples
cannot supply it. Do not describe the proposed instance as already installed.

### Composition and receipts

`Rules/FrontendBoolChain.lean:chain_after_repair_refinesC` proves:

```text
accepted repair before -> after
and proved ordinary suffix on explicit context/input domains
  => FuncRefinesC(final, Intent(exact repair.before))
```

`chain_after_repair_strict` additionally requires **intent-program support** on
that domain. Captured-source support is not a replacement. Successful nonpoison

It does not approve A2 or the model. The ordinary source-refinement and overall
chain verdict remain **abstracted** across this repair. Multiple repair checkpoints
