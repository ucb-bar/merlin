# Plan retained public development admission

`development_admission_plan` consumes the exact operator-selected readiness
handoff and its original source/reference/role inventories. It emits a bounded
job plan for all243 retained members; it executes no capture, compiler or target
and grants no seal, role, private exclusion, realization or writer authority.

```sh
python -m merlin_experiments.phase0.development_admission_plan \
  --readiness-pins "$READINESS/final-pins.json" --sha256 "$EXPECTED_SHA256" \
  --output "$TASK_DIR/.tmp/development-admission-plan.json"
```

The CLI uses one original shared CPU leaf. Input metadata is bounded to8MiB per
file and32MiB total. Selected source and complete reference leaves are reopened
before and after planning. Original NPZ/reference supplements retain their
request/manifest/output correspondence. All original243 identities,90
requirements, objective/guard intent, numerical policies and historical refusals
remain in the plan. A changed or missing pin refuses instead of producing a
partially attributed plan. No array generation or semantic reference replay runs.

The initial order is166,34,35 andengineering5:0. Only166 is the first proposed
source/profile preflight; every subsequent job depends on that member's complete
current cost and result. Each proposed job records finite90CPU/300wall/1GiB
limits,128MiB output ceiling and the unchanged64MiB file ceiling. These are proposed ceilings, not a
cost prediction, resource reservation or authorization. Remaining members stay
NOT_SELECTED_INITIAL_BATCH, never fabricated compiler refusals.

Coverage can be joined by an exact existing original declared purpose and
requirement identity. Otherwise an unmapped member retains
REFUSED_UNMAPPED_REQUIREMENT. This does not rewrite the original90requirements
or infer a physical mechanism from shapes. Refused/unavailable sources remain
mandatory accounting rows. The thirteen currently unmapped source/effect cases
therefore remain precise coverage obligations until an original binding exists.

Actual work still uses the original `development_sealed_batch.prepare`, complete
reference intake, current profile/private-exclusion/role owners, selected compiler
and linked-ELF execution service, actual source-product correspondence and writer.
The planner cannot mint any of these from saved verdicts. LegacyV23 receipts and
portable reconstructed descriptors do not becomeV26 admission. Select all actual
runtime/library/ABI contracts separately, preserve source arithmetic and every
live-out, and obtain a new bounded execution admission before running a job.
