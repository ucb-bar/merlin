# Torch 2.16 AVX2 f32 LayerNorm source arithmetic probe

The trained SpectFormer TorchAO W8A8 full-logit host comparison still fails its
unchanged source gate. This probe isolates a repeatable float difference before
the first dynamic signed-i8 activation quantizer. It changes no compiler policy,
quantization, ABI, golden, or tolerance.

## Bound source and inputs

The source wheel is Torch `2.16.0.dev20261104+cpu`, commit
`7f24a19c0967db04f2d5ba44c1e56eca489932ec`; CPU dispatch reports AVX2.
The relevant installed source header is
`torch/include/ATen/native/cpu/moments_utils.h`, specifically
`RowwiseMomentsImpl`, `UpdateMomentsVec`, `AddMomentsVec`, and `AddMoments`.
The trained checkpoint loaded with zero missing and zero unexpected keys;
TorchAO `int8_dyn_act_int8_weight` was applied explicitly. The two same-input
inputs are the saved host block-0 filter outputs `view_2` from the existing
trained and independent holdout taps; a NumPy seed-12 random tensor is a third
case. Each input has 196 f32 rows of width 256. The trained and holdout
archives are cited by the earlier
[repeated-float report](spectformer_torchao_repeated_float_ops_2026-11-06.md).

## Exact result

The existing captured LayerNorm decomposition computes each row's mean and
centered variance with serial f32 additions. Replaying those operations on
the identical saved host filter input reproduces host `layer_norm_1` **bitwise**
for both images. On that same input, Torch native LayerNorm differs from host
by relative L2 `1.571977e-7` trained and `1.611917e-7` holdout. The native
mean differs by up to `5.82e-10`/`5.24e-10`, and native reciprocal standard
deviation by up to `4.58e-5`/`5.34e-5`, respectively. The existing activation
code probe confirms that the float drift crosses TorchAO's legitimate
`-127.5` endpoint ties; the signed-i8 quantizer and matrix operation match
bitwise on identical float input.

The [standalone C++ source](torch216_avx2_ln256_probe.cpp) reconstructs the
source AVX2 width-256 arithmetic: two 16-vector chunks of eight f32 lanes,
Welford lane updates using FMA, the two-chunk cascade merge, scalar lane
merges, variance division, reciprocal square root, and affine FMA. The scalar
`AddMoments` association `m2 += (m2_add + correction)` matters: changing it to
left-associated addition failed 46–59 of 196 reciprocal-standard-deviation
rows. The [runner](torch216_avx2_ln256_probe.py) refuses any Torch source
commit or CPU capability other than the captured ones, loads the unchanged
checkpoint, applies TorchAO, and compares the C++ output to
`aten.native_layer_norm` bitwise.

| Trained host filter | 196/196 | 196/196 | 50,176/50,176 |

Build the small standalone probe into a managed task's `.tmp` directory with
`g++ -O2 -std=c++20 -fPIC -shared -mavx2 -mfma -ffp-contract=fast`, then run
the Python script with `--library`, `--trained-tap`, `--holdout-tap`,
`--model2mlir`, `--spectformer-dir`, and `--checkpoint`. This test neither
compiles a model nor calls a device. The prebuilt model kernel cache is not
needed.

## Compiler integration boundary

The current `cpu_layer_norm.py` builder is an **unwired** Torch 2.10 BF16
width-768 experiment, with different vector packing and chunk/tail behavior.
The captured f32 width-256 op is already expanded into a multi-operation
mean/variance/affine region. Reusing the BF16 builder or replacing only one
sum cannot encode the proven f32 source behavior. A production rewrite must:

1. Require an explicit Torch-CPU-AVX2-f32-LayerNorm pass switch and exact
   source commit, AVX2 dispatch, and TorchAO scheme from capture metadata.
   Refuse missing or wrong source facts; leave the default lowering unchanged.
2. Match `aten.native_layer_norm` semantics with f32 contiguous last-axis
   width 256, finite positive epsilon, f32 gamma/beta, and the exact region
   operands. Select by operation and numeric contract, not a model name or
   captured region ID. Refuse other widths, dtypes, tails, and malformed IR.
3. Emit the Welford and affine operation order proved above using explicit
   `math.fma` at the source FMA points. Preserve the scalar merge association
   and prohibit compiler reassociation that would erase the source order.
   Replace the complete native LayerNorm region, including affine output.
4. Check generated host code against the three bitwise cases above, then
   replay unchanged trained and holdout complete logits through a fresh
   compile when memory permits. Preserve strict framework comparison and
   signed-i8 OPU/VME activation ABI. Check device support for the new f32
   region separately before using it in a FireSim or Kodiak claim.

No production rewrite is committed here: the multi-operation region rewrite,
source metadata path, and generated-code bitwise gate are a separate compiler
change. This standalone proof does not imply that fixing LayerNorm alone will
pass the 1,000-logit gate. The patch convolution and FFT also show source
arithmetic differences, and repeated block drift remains to be tested.
