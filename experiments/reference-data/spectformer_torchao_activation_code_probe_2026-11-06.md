# SpectFormer TorchAO W8A8: first fc1 activation-code amplification

The trained and independent holdout images both reproduce the first fc1 exactly when TorchAO receives Merlin's saved block-0 norm2 tensor: activation bytes, reciprocal scales, i32 matrix output, and f32 fc1 output all match bitwise. Replacing only that norm2 tensor with Torch's norm2 result from the **same saved filter input** changes a few activation bytes at the negative per-row maximum. Those changes explain nearly all of the local fc1 output delta. This is a numerical sensitivity of the captured source quantizer to earlier float arithmetic; it is not evidence of an OPU or VME integer arithmetic error. The complete 1,000-logit source framework gate still fails.

## Inputs and method

The exact trained capture has `model.mlir` SHA-256 `9ae3f772ed2d192899cea502e5dec0098d5abf95f56f1707c7ba3cdfcf5481ab`; the trained checkpoint SHA-256 is `77cacfdbe53f3615666291d2a9c45aa6dd9132e48e0448bee90c3a3f1a116e3e`. Its saved host dispatch taps have archive SHA-256 `88e4a74088aec5f09cb97407c15ab315ea9b911727a003c4f433d5522ecf84df`. The holdout is the independent NumPy image from the [repeated float-op report](spectformer_torchao_repeated_float_ops_2026-11-06.md). A cache-only replay captured its block-0 norm2, activation reciprocal, signed i8 bytes, i32 fc1 result and f32 fc1 result; the tap archive SHA-256 is `4af379f6a161f1992543a78cfa1a31be33f5c7874dd17f5d4637fac70d4eb894`. Its complete host output reproduced the previously saved holdout output bitwise (SHA-256 `08d9cc56f5262ee548db6cbdd922ac414c2abc8b2038804fe77b0b8b740c7a0e`). The cache held already compiled libraries; a guard raised on any compilation request. No JIT, Spike, or FireSim run occurred.

The [probe script](spectformer_torchao_activation_code_probe.py) loads the unchanged checkpoint with Torch `2.16.0.dev20261104+cpu` and TorchAO `0.18.0`. It intercepts TorchAO's actual `Int8Tensor` activation quantizer and `aten._int_mm`, then calls block-0 fc1 with (a) saved host norm2 and (b) Torch norm2 computed from the same saved host filter output. For each image, it checks Torch's case (a) against the saved host i8 codes, reciprocal scales, i32 output, and f32 output before examining case (b). The [machine-readable result](spectformer_torchao_activation_codes_2026-11-06.json) binds tensor hashes and five changed-code examples per image.

## Result

| Input | Changed i8 codes / 50,176 | Token rows | Changed i32 outputs / 200,704 | fc1 relative L2 | fc1 maximum absolute delta |
| --- | ---: | ---: | ---: | ---: | ---: |
| Trained | 12 | 12 | 11,161 | `1.087135e-4` | `0.03696251` |
| Holdout | 16 | 16 | 14,776 | `1.214196e-4` | `0.04187727` |

Every changed activation byte is the **negative maximum-absolute channel of its token row** in both inputs. The only transitions are `-127 → -128` (7 trained, 11 holdout) and `-128 → -127` (5 each). Dividing the observed input by its actual TorchAO scale places every changed value within `5.8e-6` of `-127.5`. The source graph's per-row `max|x| / 127.5` scale makes that endpoint a rounding tie; tiny changes in norm2 values and their scales select neighboring signed codes. The largest observed scale changes are `4.47e-8` trained and `8.94e-8` holdout; 133 and 127 of 196 row scales change bit patterns. The source's `[-128,127]` clamp and round-even policy are unchanged.

To separate code and scale effects, the probe uses the observed i32 matrices and TorchAO's actual activation and per-channel weight scales. With the original scale held fixed, the i32-code term's L2 norm is `99.9998%` of the observed trained fc1 delta and `99.9983%` of the holdout delta; the remaining vector after subtracting that term is only `0.0215%` and `0.0209%` of the observed delta norm. The scale-only term is about `0.017%` of the observed delta norm in each image. These are **local float64 decompositions of the block-0 fc1 delta**, with small residuals from f32 operation rounding. They do not assign the complete model's final error to this one layer.

The exact same-input checks establish that the captured quantization arithmetic and signed i8×i8→i32 fc1 matrix root are faithful at this boundary. The preceding [FFT stage probe](spectformer_torchao_fft_stage_probe_2026-11-06.md) locates a small earlier float difference in forward FFT; this experiment proves that small float differences can be amplified at fc1's negative endpoint. It does not establish that fixing FFT alone would clear the complete source gate. A candidate float-stage rewrite must be tested on the unchanged full trained output and holdout. Altering the quantizer to avoid this tie would change the TorchAO source contract and reference, so it is not a fidelity fix for the current capture.
