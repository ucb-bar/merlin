# Full TinyLlama attention host build

`tools/tiny_full/build_attention.py` is the versioned penguin26 attention build adapter. It accepts `atlas.tiny_attention_contract.v1` / `tiny-attention` assets directly. The projection-only `build_host.py`, `KernelAssets`, and `FullBundle` formats retain their existing meaning. See [the export command](tiny-attention-export.md) for capture-to-assets preparation.

The adapter accepts the complete 22-layer prefill and two-decode bundle, its checksum-pinned original RTL qualification receipt, a Merlin comparisons source directory, an external platform tree, and an explicit RISC-V GNU toolchain bin directory. The historical attention-only inventory has 906 launches: 840 projection panels and 66 attention panels. Post-attention norm adds 66 launches for 972 total; pre-attention norm adds another 66 for the current 1,038 total and 132 norm panels. These scopes are selected by the bundle's `post_o_norm` and `pre_attention_norm` flags, not by a builder argument. Each scope checks its interleaved launch plan, every initial/output/final arena, the receipt's original-model and DMA bindings, and all 137 final cache, logits, and token buffers. The adapter also supports an explicitly marked complete layer-0 prefill block; that scope does not qualify the full model. `--out` must name a fresh directory. The build does not execute the ELF or rerun numerical qualification.

From a fresh checkout, use physical absolute paths for the exported assets, receipt, Merlin source, and toolchain, with the variables in [model bringup setup](../README.md#build) and [Inputs and environments](bringing-up-a-model.md#inputs-and-environments). The build reads the explicitly supplied platform tree, model receipt inputs, source directories, and toolchain.

```sh
"$MODEL_PYTHON" -B tools/tiny_full/build_attention.py \
  --assets "$TINY_ASSETS" \
  --qualification "$TINY_QUALIFICATION" \
  --qualification-sha256 "$TINY_QUALIFICATION_SHA256" \
  --merlin "$MERLIN/examples/atlas/comparisons" \
  --model-root "$MODEL47" \
  --receipt-data-root "$TINY_WORK_ROOT" \
  --platform-root "$PLATFORM_ROOT" --toolchain-bin "$RISCV_BIN" \
  --variant sims --jobs 2 --cmake cmake \
  --out "$TINY_DEFAULT"
```

Repeat with `--variant chip` and a different `--out`. The ELF is `OUT/build/atlas-tinyllama.elf`; `OUT/build.json` binds its SHA-256, all compiled source/header bookends, the toolchain libraries, the commands, the assets, the qualification receipt, and the two LOAD ranges. Configure, dependency, and build logs remain in `OUT`. Compilation needs Python with NumPy and the exporter dependencies, CMake 3.19 or later, a host Make, and the selected GNU RISC-V toolchain. Export's model execution dependencies are unnecessary during the host build.

For root-encoded receipts, `--model-root` resolves `@model/`, and `--receipt-data-root` resolves `@data/`; the checkout and `--merlin` resolve `@atlas/` and `@merlin/`. For historical absolute-path receipts, repeat `--receipt-relocate OLD=NEW` when relocating roots. Every resolved file must retain the receipt's exact bytes and hashes, including historical helper sources. Relocation does not requalify changed sources. The receipt argument is JSON, so first decompress a checksum-verified archived `.json.gz` into a separate file and pass the uncompressed JSON SHA-256.

Pass `--platform-root` explicitly to select the board-support tree for the target platform (startup code, drivers, and the penguin26 platform files). The tree supplies the TinyLlama CMake target, linker script, and scalar math support, and is kept outside this repository. The model and projection arithmetic remain in their existing tracked source files; Merlin arithmetic comes from the explicit `--merlin` directory. The unchanged qualified host main is `tools/tiny_full/tinyllama_main.c`. It initializes attention panels/count/cursor and transport, enforces the interleaved plan at each launch, invokes the raw loader and coherent DMA transport, checks output bytes and preservation across the complete arena, and checks final cache/logits/tokens after every step. SIMS uses HTIF; CHIP uses UART at 3686400 baud and tohost completion.

The adapter retains the original source basenames, source and library link order, `rv64gcv_zfh` / `lp64d` / `medany`, Release `-O3 -DNDEBUG`, platform `-O1`, and model `-O2 -ffp-contract=off -fno-fast-math -fno-builtin-expf -fno-builtin-nearbyintf -fno-builtin-scalbnf -fno-builtin-pow`. It does not add debug flags. Existing toolchain library debug sections are preserved. Source paths and assembly `.incbin` paths may move without changing the ELF, with the same source bytes and toolchain. `--expected-elf-sha256` enforces a desired byte identity.

It executes the RISC-V host in QEMU and supplies exact captured Atlas replies. The recorded result for the default SIMS ELF `3b75125b` above is 1,038 exact launches, 137 exact final buffers, and tokens `[278, 3711, 5652]`. This is host execution with captured replies; numerical qualification is the separate original47 gate. Neither result establishes full-model FireSim execution or physical device timing.
