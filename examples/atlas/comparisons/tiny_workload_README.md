# TinyLlama partition ladder

These tools extend the frozen native TinyLlama comparison without changing its gate or reference. The original comparison executes BF16 parameters and host arithmetic. `tiny_workload_fp32.py` provides a separate arithmetic reference by exactly casting that same BF16 checkpoint to FP32; it does not recover an FP32 training checkpoint.

`tiny_workload_native.py` authenticates the recorded receipt, complete checkpoint, all 201 parameters, token stream, tokenizer and native source dependencies, then repeats the complete 128-token prefill and 32 teacher-forced decode session. It checks all 22 layer cache-prefix histories, masks, positions, rotary context, caller state and original complete native outputs. Exported projection operands are FP32 views of BF16 values and are labeled accordingly.

`tiny_workload_inventory.py` declares 154 decoder linears and the LM head for Atlas. Embedding, RMSNorm, complete causal grouped-query attention, rotary application, softmax, SiLU, elementwise operations and cache management stay on the native host. Physical decode programs use M32 with zero row padding; arithmetic-only decode diagnostics compute its one useful row. N-column panels preserve the current producer's 32 MiB source admission. Every panel independently quantizes B and reports its scale against the global B scale; scale equality is required before claiming unchanged unsplit target arithmetic. This policy can differ from whole-tensor quantization and must be evaluated as the actual planned policy.

`tiny_workload_block.py` executes the first prefill decoder block's seven logical projections/MLPs through 12 admitted instruction-model programs, feeding each actual target output into native continuation. Every child is admitted with its current A/B/native-C identities, all five producer helpers, nonempty source/model bookends, artifact hashes, physical packing, output bytes, guards and drained completion. Reusing a Q receipt additionally requires identical actual operands. A second cached-output replay checks every actual predecessor again; the original native model is then restored and rerun. Original 1e-4 comparisons remain unchanged and can fail.

`tiny_workload_templates.py` compiles the ten distinct physical shapes in the declared partition. Each template checks four boundary rescale patches against full reassembly. This is template compilation evidence, not complete-model compilation or execution.

`tiny_fp8_pack.py` performs exact integer VPU FP8Pack for finite raw BF16 matrices. The focused tests enumerate all finite signed BF16 codes at eight admitted scales against independent quotient/remainder RNE. `tiny_workload_full.py` uses this packer and the separately reviewed Atlas vector arithmetic module to evaluate all 155 linears over the complete frozen session. It checks every actual predecessor on replay, all cache invariants, caller state and restoration of the original native model. It is explicitly arithmetic-only and provides no instruction-model, RTL, target runtime or host-ELF evidence. Its first-block word payloads can be coupled independently to admitted actual instruction-model replies.

The full arithmetic tool requires an explicit `--atlas-arithmetic` file and its `--atlas-arithmetic-sha256`. It authenticates that target provider before import and records the actual imported source; no adjacent private helper copy is required. Native source versions and any Transformers compatibility shim remain explicit external environment dependencies. Child model processes remove the native PYTHONPATH to avoid mixing incompatible NumPy installations. No package installation or environment synchronization is performed. Fixed-input host ELF reproduction has a separate [data recipe and build contract](BLOCK_REPRODUCTION.md).

The native tools accept explicit canonical paths, immutable receipt SHA-256 values and fresh output directories. Use `--help` for required flags. The full arithmetic tool enforces one available CPU, a 24 GiB RSS ceiling and a configurable wall limit; an external supervisor should also terminate the owned process group on its resource deadline. Keep executable helper snapshots immutable throughout execution and verify source bookends before publishing a result.

Run the focused controls from the Merlin root with its src directory on PYTHONPATH and explicit files: `merlin/tests/runtime/test_workload_replay_admission.py`, `test_tiny_workload_partition.py` and `test_tiny_fp8_pack.py`. Disable unrelated pytest plugin autoload, set `--confcutdir=merlin/tests/runtime`, and put pytest caches and temporary files in an owned scratch directory. These tests do not replace native, instruction-model or retained-core gates.

Recorded quality diagnostics include informational relaxations of failing original FP32-style gates; those strict failures remain recorded. Integrated task-quality accuracy is not yet measured. No existing tolerance, expected output, frozen token set or native reference is altered. A retained-core constant-DBG0 marker diagnostic is distinct from the raw host runtime's fresh sequence protocol and must be labeled separately. No full-SoC, FireSim or FPGA run follows from these tools alone.

The existing Atlas `virtual_attention_tile.mlir` composes 32x32 FP8 QK, BF16 row reductions/exp2/reciprocal, unit-scale FP8 probability packing and PV, with a sqrt32 scaling constant. The pinned native Tiny contract instead uses head 64, 32 query heads grouped over 4 KV heads, 128-position prefill and 129–160-position cached decode, full-key-axis FP32 softmax and causal masks. A valid multi-tile replacement must combine maxima and denominator sums across all key-column tiles, accumulate two head-dimension K tiles, map eight query heads per KV head, apply absolute-position masks and RoPE, and preserve each of 22 cache prefixes while appending actual new tails. The current partition keeps attention on the host because this complete workload composition is absent from the admitted path; it does not deny the existing Atlas tile attention and softmax capabilities. Applying independent 32-column softmax tiles would be numerically incorrect for the complete key axis.
