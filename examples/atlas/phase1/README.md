## Kernel library

`kernel_library/` follows the Radiance [research treatment](../../radiance/phase1/README.md): a pinned selection and reproducible export for read-only authoring evidence. Selection remains disabled, the target descriptor grants no library treatment, and no Atlas compiler or runtime consumes this catalog. Submitted packages may not copy kernel bodies, link or call the reference library, or dispatch by capsule name or expected output. Materialization does not authorize execution or establish numerical qualification.

The single catalog pin is atlas-kernels [`ce465827a977ba8451b585f71910726e7f12b885`](https://github.com/ucb-bar/atlas-kernels/commit/ce465827a977ba8451b585f71910726e7f12b885). The current [Qwen full-model runner](../model_bringup/qwen/full_model/run.py) explicitly requires this revision, including epsilon propagation, captured projection staging, and guarded wide-attention loop completion. `model_bringup/source-map.json` records `f9be646` as the older relocation snapshot; it is historical provenance, not the current bringup requirement. The chosen revision is reachable from the locally available public `origin/feat/kernel-library` at `0333da0`; that later commit changes coverage documentation and images. Neither the stale README pin nor the moving branch tip determines this catalog's revision.

`selection.yaml` is generated by `generate_selection.py`, which reads every input with `git show` at that exact revision. Radiance has a handwritten selection and no selection generator. Atlas retains its manifest-driven generator: reviewed prose forms in `kernels/*/kernel.yaml` supply the shape bounds and sets, and unrecognized forms fail generation. Semantic aliases, hardware capabilities, priorities, and the choice of catalog variant remain reviewed metadata in the generator. Coverage placement checks declared dtypes, emitted transcendental capabilities, projection variant M/K/N, and placed Linear K/N; it does not prove every placed operation or full model coverage.

The shared matcher preserves Radiance's v1 field names and adds four shape predicates understood by the shared authoring matcher (`merlin.targetgen.kernel_family_selection`): `one_of` for exact integer sets, `power_of_two: true`, `multiple_of_dimension` for divisibility by another required dimension, and `tile_product_max` for descriptor capacity across tiled dimensions. Missing dimensions refuse a candidate. The retained reference-provider snapshot remains unchanged; the shared matcher does not register an Atlas compiler or runtime consumer. The nine catalog families have these scopes:

- Projection GEMM and fused epilogue/RNE-add use positive multiples of 32 for M, K, and N. Traffic-reuse recipes remain internal to the library's exact-shape dispatch.
- Producer-fused RoPE uses the manifest's complete producer shape set: M in {32, 128}, K = 2048, N in {256, 2048}, and head dimension 64. Standalone BF16 RoPE is outside this catalog.
- RMSNorm uses physical rows in {32, 128} and widths from 32 through 7136 in steps of 32. Logical width must equal physical width; decode may pad one logical row to 32 physical rows. Epsilon must separately satisfy the library's positive finite-normal BF16 policy. Widths 960 and 2048 at default epsilon retain the resident implementation; other admitted cases use streaming.
- Attention describes dimension-64 v2 only: logical Sq from 1 through 4096, Sk from 1 through 2048, and positive query/KV heads with query heads divisible by KV heads, and `ceil(Sq/32) * ceil(Sk/32) <= 2048` for descriptor storage. The catalog describes ordinary padded head tiles (`packed_decode=False`), avoiding the packed-decode group limit. Mask storage, scales, and arena bounds still require independent admission. Wide-head and vision-fast variants are outside this catalog because their additional correlated resource, mask, and numerical contracts are not represented here.
- Smol bias/GELU fusion retains the manifest's 128x768x3072 fc1 shape.
- Max pool is restricted to the manifest's qualified stem: channels 64, height/width 112, kernel 3, stride 2, and padding 1. The broader generator has correlated register-group and VMEM limits that the catalog does not encode. Exactness also requires nonnegative normal FP8 input.
- Patch gather requires power-of-two channels divisible by 32, kernel in {1, 3}, stride in {1, 2}, and positive output channels divisible by 32. Same padding, physical M/K consistency, the blocked recipe for 3x3, and DMA bounds remain separate composition checks.

Four catalog paths describe stages fused into `projection_gemm`: `epilogue`, `rne_add`, `rope`, and `resnet_patch_gather`. They use compound semantic operations, following Radiance's `matmul_rope` treatment, and each generated comment records the manifest stage. The newer library's opt-in standalone epilogue, RNE-add, and RoPE entry points are not selected by these compound rules. A family match identifies a candidate strategy, not permission to execute a kernel or an extension of its arithmetic evidence.

To regenerate and check from the repository root:

```sh
python examples/atlas/phase1/kernel_library/generate_selection.py --checkout /path/to/atlas-kernels
python examples/atlas/phase1/kernel_library/generate_selection.py --checkout /path/to/atlas-kernels --check
```

Set `MERLIN_ATLAS_KERNELS` instead of `--checkout` if desired. Set `MERLIN_ATLAS_MLIR` to additionally require that checkout's `HEAD` gitlink at `third_party/atlas-kernels` to equal the selection revision; a missing or different gitlink fails. Without it, the comparison is reported as `not-checked`. This optional comparison does not claim that an arbitrary atlas-mlir checkout already uses the chosen pin. A pin update requires a public revision admitted by the bringup, regeneration, documentation review, and an updated selection digest in `merlin/tests/infra/test_atlas_kernel_library_example.py`.

To materialize authoring evidence:

```sh
python examples/atlas/phase1/kernel_library/materialize.py --checkout /path/to/atlas-kernels
```

The default output is `out/artifacts/targets/atlas/kernel_library_v1`, honoring `MERLIN_OUT_ROOT`; `--output` selects another destination. The exporter archives only the pinned shared paths and nine family directories, then records selection and payload SHA-256 digests, file/byte counts, and source identity. It exports no `coverage/` model inventories. Like Radiance, it reuses only an identical complete tree, refuses changed artifacts without overwriting them, and rejects symlinks. Local source-access exclusions additionally prune restricted path names before traversal and archive export. It never compiles, links, or calls a reference kernel.

Run the checkout-dependent regression tests with a checkout containing the pin and the public `origin/feat/kernel-library` tracking ref:

```sh
MERLIN_ATLAS_KERNELS=/path/to/atlas-kernels python -m pytest merlin/tests/infra/test_atlas_kernel_library_example.py merlin/tests/infra/test_kernel_selection_constraints.py merlin/tests/infra/test_radiance_kernel_library_example.py -q
```

The current `pr-fast` workflow does not provision the kernel checkout. Checkout-dependent tests skip only when `MERLIN_ATLAS_KERNELS` is absent and fail if it is explicitly unusable. TinyLlama, SmolVLA, and ResNet50 remain held-out validation models; enabling model-directed library evidence requires a separate research-policy decision and an explicit information grant. This repair adds neither.
