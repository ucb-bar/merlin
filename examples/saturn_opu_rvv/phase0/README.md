# Saturn OPU RVV: Phase 0 — hardware-guided test generation

Start with [the experiment definition](../experiment.yaml), catalog ID
`saturn-opu-rvv-functional`, runtime target `saturn_opu_mxv256d128_rvv`.

[`recipe.yaml`](recipe.yaml) is the authored public coverage recipe, not a generated
corpus or evidence of hardware correctness. The definition explicitly names its shared
`performance_template` and generated `synth_profile` / `smt_profile` inputs.
Private `hidden_profile` stays outside examples; never copy holdouts, goldens, weights,
or generated capsules here. Optional sidecars may be absent; frozen runs bind their
presence as well as their bytes.

The authored descriptor lives at
[`target/descriptor.yaml`](../target/descriptor.yaml); its `resources_root`
still selects retained native resources.
This is not yet a self-contained target package. Install Merlin plus
`merlin-experiments`, provision the selected OOT support and the descriptor's declared
inputs, and make any required capture/toolchain dependencies available before running.
An example recipe does not establish simulator, RTL, hardware, or model-download availability.

The mesh-assertion release gate cannot evaluate this target until its generated capability
contract exists. With a selected MLC checkout containing this physical unit's cached state
manifest and HW MLIR, generate it explicitly:

```sh
MERLIN_MLC_DIR=/path/to/modeling python build_tools/scripts/gen_saturn_opu_rvv_contract.py \
  --facts-from saturn_opu_mxv256d128
python build_tools/scripts/check_mesh_assertion_not_weakened.py \
  --target saturn_opu_mxv256d128_rvv
```

The generator writes `out/artifacts/targets/saturn_opu_mxv256d128_rvv/contracts/target_contract.yaml`
and a sibling `target_contract.generation.json` receipt with hashes of the exact descriptor,
residual, state manifest, HW MLIR, and generated contract. These are **generated outputs**, not
authored example inputs. The cached MLC arc currently has no machine-readable source commit; its
receipt therefore says `hardware_pin_status: unverified_cached_arc_source_revision`. A green
mesh-assertion gate establishes consistency against those generated bytes, **not** a verified
Saturn RTL pin, simulator result, hardware verdict, or eligible publication claim. On machines
without generated contracts, CI prints those targets as `UNQUALIFIED`; the full gate without
`--allow-unresolved` still refuses them.

Inspect first; then use fresh paths under your configured output root. Replace
`/configured/out` below with that root:

```sh
merlin experiment inspect saturn-opu-rvv-functional --phase 0
merlin experiment preflight saturn-opu-rvv-functional --phase 0
merlin experiment run saturn-opu-rvv-functional --phase 0 --run-dir /configured/out/runs/saturn_opu_mxv256d128_rvv/phase0/example-1
merlin experiment corpus prepare /configured/out/runs/saturn_opu_mxv256d128_rvv/phase0/example-1 --output /configured/out/artifacts/protocols/saturn_opu_rvv-review-1
merlin experiment corpus inspect /configured/out/artifacts/protocols/saturn_opu_rvv-review-1
```

Stop for human review of the prepared inputs and owner-only diagnostics. **Only after
review**, acknowledge the exact inspected digest:

```sh
merlin experiment corpus seal /configured/out/artifacts/protocols/saturn_opu_rvv-review-1 \
  --expected-digest DIGEST_FROM_INSPECT --reviewed-by OPERATOR --review-note REVIEW_SUMMARY
```

The seal records a review acknowledgement, not numerical or hardware certification.
It does not automatically approve or start Phase 1. Follow the
[shared reviewed handoff](../../../experiments/README.md#reviewed-phase-0-handoff)
to select the reviewed release explicitly; retain old run receipts unchanged.
