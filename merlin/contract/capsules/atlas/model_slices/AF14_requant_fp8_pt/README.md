# AF14_requant_fp8_pt

AF14_requant_fp8_pt ports npu_model's `smolvla_requant`: bf16 -> fp8_e4m3 at unit scale (`seli` imm=1). Execution reference: atlas-npu `baremetal/assembly/smolvla_requant.S`, which packs the two 32x16 bf16 halves through `VPACK.BF16.FP8`; no VTRPOSE, because nothing is pushed into the MXU. DTYPE -- option (a): the fp8 round trip is IN the program, spelled `arith.truncf ... : f32 to f8E4M3FN` inside the linalg body exactly as npu_model's own REQUANT_MLIR spells it, so the bf16 tensor dtype declared in capsule.yaml and the tensor dtype in capsule.interface.mlir agree and the quantization is the thing being graded rather than a footnote. The interface module is AUTHORED rather than captured: model2MLIR lowers `x.to(float8_e4m3fn).to(bf16)` to bf16 -> f32 -> bf16, an identity, so a captured module would not contain the quantization its own golden was computed with. The golden is still the host torch-eager result of capsule.pytorch.py, which does round. Inputs span +-64 deliberately: on [-1, 1) the fp8 rounding error is a few hundredths, and at the tolerance a float corpus declares a plain COPY of the input would pass.
