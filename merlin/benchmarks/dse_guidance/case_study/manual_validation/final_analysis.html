KV formula — validated on the IR, applied at scale

KV bytes = 2·kv_heads·head_dim·seq·n_layers·dtype. On openVLA’s captured config the formula reproduces the IR iter_arg exactly (2·4·128·27·2·4 = 221,184 B), then the same formula at the Llama-2-7B deployment config gives 137.9 MB (bf16).

The byte formula is anchored to the IR, not asserted — then composed to deployment scale (weight values are irrelevant to the shape contract).

3 · Headline results (each verified against source)

Primitive-set frontier — search SETS, not one tile

Best single primitive (gemv_lane_64) covers the worst workload at only 0.039; the best 2-set gemv_lane_64 + tile_8x16 lifts worst-workload coverage to 0.998 (macro 1.000).

Robust across pad-waste 5/10/20% and leave-one-out — but the specific pair is threshold-sensitive once finer tiles are added (linear-GEMM coverage only; attention excluded). A search-space construction claim, not a performance claim.

Operator concentration — two regimes

rdt: top op = 87% of MACs (depth-2 artifact — see §4).
pi05: 777 ops, only 17 distinct shapes; 34 ops to reach 50% MACs → instance concentration, not shape diversity.

Abstraction necessity (strict)

4 necessary · 5 useful · 11 possible · 7 blocked · 0 N/A

Not “everything supported”. Low-bit abstractions were correctly blocked by capture (now resolved, §0); matrix_engine necessary for only 2/11 (corpus-narrow); skinny_gemm_or_gemv_engine necessary 9/11.

Capture fidelity — the central result

Preserved: op shapes, region roles, dtype, attention/softmax/norm (re-parsed from generics). Now also recovered (P21): the K-loop, KV-state, loop-carried state — from scf.for in the loop-preserving captures (the other 8 workloads still honestly show assumed/erased until wrapped).

Demonstrated from IR, not asserted: the matrix cells read recovered (K=N, IR scf.for) / recovered (B, IR iter_arg) for smolVLA / openVLA / pi0.5.

Residency & requirements envelope

Reload grows with K, resident is flat; int4 < int8 < bf16 capacity. Requirement envelopes (work ÷ deadline) over deadline/K/H grids — a requirement, never measured.

K is now IR-recovered for the loop-preserving captures (was configured/reference).

4 · Forensic verdict — source-grounded, one workload at a time

Every claim below cites a repo file:line / exported-FX op / MLIR snippet (full detail per workload in manual_validation/<wl>_source_to_mlir_audit.md).

Faithful

  • rdt 87% giant op is a real nn.Linear(2048,4096) over a 4096-token image context.
  • bitvla low-bit: source has real int2 BitLinear packing — and P21 now captures it natively (§0).
  • xr0 3D-fold MACs are exact; pi05 “17 distinct shapes” confirmed correct (the doubt was a CSV misparse).

Bugs found & fixed

  • xr0 attention under-counted → SDPA-fused attention (prov.op=sdpa) was missed; recovered 0 → 14 ops, fraction 1.0 → 0.992.
  • groot attention over-counted → CategorySpecificMLP bmm mislabeled attention; 11 → 4 true + 7 batched_matmul (341M MACs separated).
  • xr0 K drift 10 → 5 (source num_steps=5).

Resolved with evidence (P20-S3 + P21)

  • rdt “one giant op” = confirmed depth-2 artifact: at depth-6 the top-op share drops 0.871 → 0.292 (cross-attn-KV is the dominant class ~88%, distributed, not one op).
  • “GEMV is capture-M”: tiny_llama at true decode M=1 is also gemv_like (= the captured M=4) → the GEMV finding genuinely holds in the decode regime.
  • K / KV-state / loop-carried state / region roles / magnitudes / native low-bit — all resolved in P21 (§0): IR scf.for, config-exact composition, and the bitvla native-ternary capture.

True, but state the caveat

  • The 8 workloads without a loop-preserving wrapper yet still rest on configured K (smolVLA / openVLA / pi0.5 are now IR-recovered).
  • Magnitudes for the small captures are structural-only; the deployment-real magnitudes (§2) are the config-exact composition.
  • The bitvla native bit-unpack arithmetic is still in opaque func.call (the model forward .item()s the scale); the packed-int2 storage + scale + placement are recovered.

7 · What’s next

The compiler capability is universal (zero per-model work); the remaining effort is per-model wrapper authoring:

  • Loop-preserving wrappers for the other 8 — the 2 LLMs + molmoact + bitvla + xr0 are mechanical (clean shape-invariant step); the RDT-family diffusion models need the sampler re-embed pulled into the loop body (their denoise step is not a clean round-trip).
  • Native bit-unpack op — name the bitvla shift/and unpack (avoid the .item() scale graph-break) so the int2→ternary arithmetic is no longer opaque.
  • Runtime/physical frontier — per-K-step wall-clock, area/energy from a design YAML — orthogonal to the static contract, out of scope by design.
